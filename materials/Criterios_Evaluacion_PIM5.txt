CATEGORÍA A EVALUAR | REQUERIMIENTO POR CATEGORÍA | EXCELENTE | SATISFACTORIO | INSUFICIENTE
Gestión del proyecto en Git y estructura (20 pts) | Implementa correctamente la estructura de carpetas y ramas. | Estructura y ramas según requerimientos, sin errores. | Estructura funcional con leves omisiones. | Estructura incorrecta o incompleta.
Uso correcto de GitHub: commits, versionado, requirements.txt. | Historial limpio, uso adecuado de versiones, archivos clave presentes. | Versionado y archivos funcionales con errores menores. | Versionado desorganizado o archivos ausentes.
Análisis exploratorio e ingeniería de datos (20 pts) | Realiza EDA completo (univariable, bivariable, multivariable). | Análisis detallado y visualmente claro, hallazgos bien documentados. | Análisis realizado pero poco profundo o mal visualizado. | EDA incompleto o desorganizado.
Aplica ingeniería de características de forma efectiva. | Transformaciones útiles, imputaciones correctas, encoding apropiado. | Aplicación funcional pero con áreas de mejora. | Transformaciones erróneas o irrelevantes.
Modelado y evaluación (25 pts) | Entrena múltiples modelos y selecciona el mejor. | Múltiples modelos comparados con base en métricas relevantes. | Modelos entrenados pero con análisis superficial. | Solo un modelo sin comparación ni justificación.
Evalúa correctamente con métricas apropiadas. | Usa ROC-AUC, F1, Precision-Recall y las interpreta correctamente. | Aplica métricas básicas sin interpretación estratégica. | Métricas mal aplicadas o ausentes.
Despliegue y monitoreo (20 pts) | Implementa API funcional con FastAPI y Docker. | API bien documentada, funcional y dockerizada. | API funcional con detalles mejorables. | API incompleta o no funcional.
Monitorea drift y desarrolla app en Streamlit. | Identifica drift y crea dashboard funcional. | Drift detectado parcialmente, visualización básica. | No realiza monitoreo o visualización pobre.
Documentación y buenas prácticas (15 pts) | Documenta el proyecto en README y código. | README claro, completo y código comentado. | README básico o con información incompleta. | Documentación muy limitada o ausente.
Integra principios de MLOps y automatización básica. | Usa scripts automatizados y flujo reproducible. | Automatización parcial o poco robusta. | Sin enfoque reproducible ni automatización.
Extra Credit: SonarCloud | Integra SonarCloud y valida calidad, seguridad y estilo del código. | Integra SonarCloud correctamente y reporta resultados de calidad del código, seguridad, cobertura de pruebas e integridad del estilo. | Integra SonarCloud parcialmente (por ejemplo, analiza solo calidad o seguridad) o el análisis tiene configuraciones limitadas. | No se integra SonarCloud al repositorio o el análisis no se ejecuta correctamente.
